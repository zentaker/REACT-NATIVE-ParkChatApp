Contexto:
La app ParkChat/Aldea está desarrollada con:
- Expo
- React Native
- TypeScript
- Expo Router
- Supabase
- Replit como workspace
- GitHub como fuente de verdad

Problema:
El usuario no puede visualizar cómodamente el avance de la app en Replit. Necesitamos estabilizar el preview para que pueda ver la interfaz al costado mientras el agente trabaja.

Estado actual conocido:
- npx expo start --web --port 5000 corre.
- Preview web ha renderizado antes.
- Typecheck pasa.
- Backend Supabase real sigue bloqueado por secret URL inválido, pero este sprint no debe depender de Supabase real.
- La app puede funcionar con mocks.
- Etapas 0, 1A, 1B, 1C están implementadas a nivel código.
- El foco actual NO es QA Supabase.
- El foco actual es visualización/preview.

Objetivo del sprint:
Dejar funcionando al menos una ruta estable de visualización:

Ruta A — Replit Web Preview:
- La app abre en el panel Preview.
- Se ve en layout mobile/responsive.
- Se puede navegar por tabs.
- Se pueden abrir pantallas principales.
- Funciona con mocks si Supabase no está configurado.

Ruta B — Expo Go:
- El proyecto puede iniciar con tunnel.
- Se muestra QR.
- El usuario puede abrirlo desde Expo Go en celular.
- Documentar si Replit no permite mantener el proceso o si el QR no aparece.

Ruta C — Replit Mobile Preview / Simulator:
- Validar si está disponible en este Repl.
- Documentar si no está disponible por tipo de proyecto, plan o configuración.

No objetivos:
- No corregir Supabase en este sprint.
- No ejecutar smoke test Supabase.
- No tocar RLS.
- No agregar Neo4j.
- No agregar matching.
- No agregar features nuevas.
- No hacer release/tag.
- No romper mocks.
- No convertir la app en web-only.
- No eliminar soporte mobile.
- No imprimir secrets.
- No subir .env.

Si ya existen equivalentes, no duplicar.

Importante:

- start:go debe ser el comando para celular con Expo Go.
- No hacer que Run principal dependa de Supabase real.
