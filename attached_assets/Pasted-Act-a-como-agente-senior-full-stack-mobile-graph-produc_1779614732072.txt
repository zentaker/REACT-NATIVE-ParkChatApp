Tarea 3 — Diseñar tablas graph-ready en Postgres

Agregar migración SQL no destructiva:

supabase/graph-ready.sql

Debe crear tablas nuevas, sin romper las 9 existentes.

Tablas sugeridas:

1. user_places
- id uuid pk
- user_id uuid references profiles(id)
- place_id uuid references places(id)
- relationship_type text default 'visited'
- last_seen_at timestamptz
- visit_count integer default 1
- created_at timestamptz
- unique(user_id, place_id)

2. topic_tags
- id uuid pk
- name text unique not null
- slug text unique not null
- created_at timestamptz

3. message_topic_tags
- id uuid pk
- message_id uuid references place_messages(id)
- topic_tag_id uuid references topic_tags(id)
- created_at timestamptz
- unique(message_id, topic_tag_id)

4. place_topics
- id uuid pk
- place_id uuid references places(id)
- topic_tag_id uuid references topic_tags(id)
- weight integer default 1
- last_activity_at timestamptz
- created_at timestamptz
- unique(place_id, topic_tag_id)

5. user_topic_interests
- id uuid pk
- user_id uuid references profiles(id)
- topic_tag_id uuid references topic_tags(id)
- source text default 'manual'
- weight integer default 1
- created_at timestamptz
- unique(user_id, topic_tag_id)

6. user_connections
- id uuid pk
- user_a uuid references profiles(id)
- user_b uuid references profiles(id)
- source text not null
- place_id uuid references places(id)
- event_id uuid references events(id)
- group_id uuid references groups(id)
- weight integer default 1
- created_at timestamptz
- unique(user_a, user_b, source, place_id, event_id, group_id)
- check user_a <> user_b

Todas deben tener:
- indexes
- RLS enabled
- safe policies básicas
- no destructive drops

Tarea 4 — Crear policies para graph-ready

Crear:

supabase/graph-ready-policies.sql

Policies mínimas:
- authenticated puede leer topic_tags.
- authenticated puede leer place_topics.
- usuario puede leer/escribir sus propios user_places.
- usuario puede leer/escribir sus propios user_topic_interests.
- message_topic_tags puede leerse si el mensaje es visible.
- user_connections lectura limitada:
  - usuario puede leer conexiones donde participa
  - opcional: agregados públicos por place, no datos privados
- inserts solo con auth.uid() donde aplique.

No abrir demasiado:
- no permitir que usuario cree conexiones arbitrarias entre terceros.
- no permitir manipular intereses de otro usuario.
- no permitir manipular user_places de otro usuario.
