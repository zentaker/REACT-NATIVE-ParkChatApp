Actúa como un agente senior de desarrollo full-stack mobile. Vas a iniciar la Etapa 0 del proyecto “Aldea”.

Aldea es una red social geoespacial donde cada lugar físico tiene una comunidad viva: chat local, grupos, eventos espontáneos y conexiones reales entre personas, temas y espacios.

La hipótesis principal del MVP es:

“¿La gente quiere entrar al espacio digital de un lugar físico y hablar con desconocidos/locales ahí?”

Por eso, NO vamos a construir todavía un grafo social completo con Neo4j. Primero debemos validar el flujo:

lugar físico → conversación → grupo/evento

Objetivo de esta Etapa 0:
Crear la fundación técnica del proyecto para que el MVP pueda desarrollarse de forma ordenada, con estructura de carpetas, rutas, pantallas base, modelo de datos inicial, cliente de Supabase, tipos TypeScript y documentación mínima.

Stack decidido:
- Expo + React Native
- TypeScript
- Expo Router
- Supabase para Auth, Postgres, Realtime y Storage inicial
- Postgres relacional como base principal
- No Neo4j en esta etapa
- No IA en esta etapa
- No matching romántico
- No monetización
- No feed global

Modelo de datos inicial en Postgres/Supabase:

Debes crear SQL para estas tablas:

profiles:
- id uuid primary key references auth.users(id)
- username text unique
- display_name text
- avatar_url text
- bio text
- safety_mode text default 'standard'
- created_at timestamptz default now()
- updated_at timestamptz default now()

places:
- id uuid primary key default gen_random_uuid()
- name text not null
- description text
- type text not null
- latitude double precision not null
- longitude double precision not null
- radius_meters integer default 150
- city text
- country text
- visibility text default 'public'
- created_at timestamptz default now()
- updated_at timestamptz default now()

user_places:
- id uuid primary key default gen_random_uuid()
- user_id uuid references profiles(id)
- place_id uuid references places(id)
- relationship_type text default 'visited'
- last_seen_at timestamptz
- visit_count integer default 1
- created_at timestamptz default now()

place_messages:
- id uuid primary key default gen_random_uuid()
- place_id uuid references places(id)
- user_id uuid references profiles(id)
- body text not null
- moderation_status text default 'visible'
- created_at timestamptz default now()

local_groups:
- id uuid primary key default gen_random_uuid()
- place_id uuid references places(id)
- created_by uuid references profiles(id)
- name text not null
- description text
- access_level text default 'public'
- member_count integer default 0
- created_at timestamptz default now()
- updated_at timestamptz default now()

group_members:
- id uuid primary key default gen_random_uuid()
- group_id uuid references local_groups(id)
- user_id uuid references profiles(id)
- role text default 'member'
- status text default 'active'
- joined_at timestamptz default now()

group_messages:
- id uuid primary key default gen_random_uuid()
- group_id uuid references local_groups(id)
- user_id uuid references profiles(id)
- body text not null
- moderation_status text default 'visible'
- created_at timestamptz default now()

local_events:
- id uuid primary key default gen_random_uuid()
- place_id uuid references places(id)
- group_id uuid references local_groups(id)
- created_by uuid references profiles(id)
- title text not null
- description text
- starts_at timestamptz not null
- ends_at timestamptz
- capacity integer
- access_level text default 'public'
- source_type text default 'place'
- source_message_id uuid references place_messages(id)
- created_at timestamptz default now()
- updated_at timestamptz default now()

event_attendees:
- id uuid primary key default gen_random_uuid()
- event_id uuid references local_events(id)
- user_id uuid references profiles(id)
- status text default 'going'
- joined_at timestamptz default now()

topic_tags:
- id uuid primary key default gen_random_uuid()
- name text unique not null
- created_at timestamptz default now()

message_topic_tags:
- id uuid primary key default gen_random_uuid()
- message_id uuid references place_messages(id)
- topic_tag_id uuid references topic_tags(id)

safety_reports:
- id uuid primary key default gen_random_uuid()
- reporter_id uuid references profiles(id)
- reported_user_id uuid references profiles(id)
- place_id uuid references places(id)
- message_id uuid references place_messages(id)
- reason text not null
- details text
- status text default 'open'
- created_at timestamptz default now()

user_blocks:
- id uuid primary key default gen_random_uuid()
- blocker_id uuid references profiles(id)
- blocked_id uuid references profiles(id)
- created_at timestamptz default now()

Crea políticas RLS iniciales en /supabase/policies.sql:

- Los lugares públicos pueden ser leídos por usuarios autenticados.
- Los mensajes visibles de un lugar pueden ser leídos por usuarios autenticados.
- Los usuarios autenticados pueden crear mensajes con su propio user_id.
- Los usuarios pueden leer grupos públicos.
- Los usuarios pueden solicitar o crear membresías usando su propio user_id.

No hace falta que las políticas sean perfectas, pero deben ser una base razonable y documentada.

Criterios de aceptación de Etapa 0:

La etapa se considera completa si:

1. El proyecto corre localmente.
2. Existe navegación base con Expo Router.
3. Hay pantallas para auth, mapa/lista de lugares, detalle de lugar, chat, grupos, eventos y perfil.
4. Hay datos mock funcionales.
5. Hay cliente Supabase configurado con variables de entorno.
6. Hay servicios separados para places, messages, groups, events y profiles.
7. Hay tipos TypeScript claros.
8. Hay SQL inicial para schema, seed y policies.
9. Hay documentación mínima en /docs.
10. No hay implementación de Neo4j.
11. No hay matching romántico.
12. No hay features fuera del MVP.
13. No se exponen coordenadas exactas de usuarios en la UI.
14. El código está organizado para que la siguiente etapa pueda implementar funcionalidades reales sin rehacer la base.

Prioridades de UX:

- La app debe sentirse como “entro a un lugar y veo su comunidad”.
- La pantalla de lugar debe ser el centro del MVP.
- El chat público del lugar debe ser fácil de encontrar.
- Los grupos y eventos deben estar claramente ligados al lugar.
- La seguridad debe aparecer desde el inicio, aunque sea como UI y documentación básica.
- Evita una estética de dating app.
- Evita una estética de marketplace.
- El producto debe sentirse comunitario, local y seguro.

Reglas de privacidad para esta etapa:

- No mostrar ubicación exacta de usuarios.
- No mostrar “Sandra está exactamente aquí”.
- Mostrar como máximo presencia agregada o estado comunitario.
- Usar textos tipo:
  “Tu ubicación exacta no se comparte públicamente.”
  “Los chats de lugar están pensados para conversaciones locales y seguras.”
- Preparar estructura para bloqueos y reportes desde el inicio.
