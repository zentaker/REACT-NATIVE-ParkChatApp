Ejecutar:

npm run doctor:node
npm run supabase:doctor-db

Confirmar:
- doctor:node OK.
- supabase:doctor-db OK.
- typecheck 0 errores.
- qa:smoke PASS.
- no secrets impresos.

Si algo falla:
- detener release.
- reportar bloqueo.
- no crear tag.

Tarea 2 — Revisar checklist release

Revisar:

docs/RELEASE_V0_1_0_CHECKLIST.md
docs/ETAPA_1D_RELEASE_QA.md

Confirmar:
- Release readiness = GO.
- No hay bloqueadores críticos.
- Limitaciones conocidas están documentadas.
- Lo pendiente post-v0.1.0 está documentado.

Si Release readiness no es GO:
- detener.
- no crear tag.

Tarea 3 — Revisar Git

Ejecutar:

git status --short
git branch
git remote -v
git log --oneline -10

Si hay cambios pendientes:
- revisarlos.
- commitear solo si son docs/checklist/release QA o fixes ya validados.

Commit sugerido si hay cambios:

git add .
git commit -m "docs: finalize v0.1.0 release candidate"

Si Git directo está bloqueado por Replit:
- reportar que el usuario debe usar Tools → Git para commit/push.
- no afirmar que se hizo commit si no se pudo.

Tarea 4 — Push a main

Si Git funciona:

git push origin main

Si push falla:
- reportar error exacto.
- no crear tag hasta que main esté actualizado en GitHub.

Tarea 5 — Verificar workflow de release

Revisar:

.github/workflows/release.yml

Confirmar:
- trigger por tags v*
- permissions contents: write
- crea bundle sin node_modules, .env, .expo, dist, web-build.
- usa gh release create o action equivalente.
- no incluye secrets.

Si falta workflow:
- crearlo o corregirlo.
- commitear/pushear.
- no crear tag hasta que workflow esté en main.

Tarea 6 — Crear tag v0.1.0

Antes de crear tag, verificar que no exista:

git tag --list "v0.1.0"

Si ya existe:
- no recrearlo.
- reportar estado.
- verificar release existente.

Si no existe y todo está OK:

git tag v0.1.0
git push origin v0.1.0

Tarea 7 — Verificar GitHub Release

Después de push tag:
- verificar que GitHub Actions corrió.
- verificar que se creó release v0.1.0.
- verificar que el bundle no contiene:
  - .env
  - node_modules
  - .expo
  - secrets
  - dist viejo
- documentar URL o estado del release si está disponible.

Si no puede verificar desde Replit:
- indicar al usuario que revise GitHub → Actions / Releases.
- documentar comandos/acciones pendientes.
