Objetivo de Stage 2A:
Crear una capa graph-ready sobre Supabase/Postgres para empezar a capturar y visualizar relaciones sociales/contextuales sin introducir Neo4j todavía.

El producto debe empezar a modelar:

usuario ↔ lugar
usuario ↔ grupo
usuario ↔ evento
usuario ↔ tema
mensaje ↔ tema
lugar ↔ tema
usuario ↔ usuario

Hipótesis de producto:
“Cada lugar físico puede tener una comunidad viva: chat local, grupos, eventos y relaciones entre personas, temas y espacios.”

Resultado esperado:
Al terminar Stage 2A, la app debe poder:
1. Registrar relación usuario-lugar cuando alguien entra o interactúa con un lugar.
2. Extraer hashtags simples desde mensajes.
3. Crear topic tags.
4. Asociar mensajes con topics.
5. Asociar lugares con topics activos.
6. Registrar intereses básicos de usuario.
7. Mostrar temas activos en el detalle del lugar.
8. Mostrar intereses del usuario en el perfil.
9. Validar RLS de relaciones propias.
10. Mantener Stage 1 intacto.

No objetivos:
- No introducir Neo4j todavía.
- No agregar una nueva base de datos.
- No agregar matching romántico.
- No agregar feed global.
- No agregar IA generativa.

- No exponer secrets.
- No desactivar RLS.
- No hacer rediseño completo.
- No mostrar ubicación exacta de usuarios.
- No mostrar presencia individual sensible tipo “Sandra está aquí”.

Tarea 3 — Diseñar schema graph-ready en Postgres

Crear:

supabase/graph-ready.sql

Debe ser idempotente y no destructivo.

Crear estas tablas:

1. user_places

Campos:
- id uuid primary key default gen_random_uuid()
- user_id uuid not null references profiles(id) on delete cascade
- place_id uuid not null references places(id) on delete cascade
- relationship_type text not null default 'visited'
- last_seen_at timestamptz default now()
- visit_count integer not null default 1
- created_at timestamptz default now()
- updated_at timestamptz default now()
- unique(user_id, place_id)

relationship_type permitido:
- visited
- active
- joined
- hosted
- interested

2. topic_tags

Campos:
- id uuid primary key default gen_random_uuid()
- name text not null unique
- slug text not null unique
- created_at timestamptz default now()

3. message_topic_tags

Campos:
- id uuid primary key default gen_random_uuid()
- message_id uuid not null references place_messages(id) on delete cascade
- topic_tag_id uuid not null references topic_tags(id) on delete cascade
- created_at timestamptz default now()
- unique(message_id, topic_tag_id)

4. place_topics

Campos:
- id uuid primary key default gen_random_uuid()
- place_id uuid not null references places(id) on delete cascade
- topic_tag_id uuid not null references topic_tags(id) on delete cascade
- weight integer not null default 1
- last_activity_at timestamptz default now()
- created_at timestamptz default now()
- updated_at timestamptz default now()
- unique(place_id, topic_tag_id)

5. user_topic_interests

Campos:
- id uuid primary key default gen_random_uuid()
- user_id uuid not null references profiles(id) on delete cascade
- topic_tag_id uuid not null references topic_tags(id) on delete cascade
- source text not null default 'manual'
- weight integer not null default 1
- created_at timestamptz default now()
- updated_at timestamptz default now()
- unique(user_id, topic_tag_id)

source permitido:
- manual
- hashtag
- event
- group
- message

6. user_connections

Campos:
- id uuid primary key default gen_random_uuid()
- user_a uuid not null references profiles(id) on delete cascade
- user_b uuid not null references profiles(id) on delete cascade
- source text not null
- place_id uuid references places(id) on delete set null
- event_id uuid references events(id) on delete set null
- group_id uuid references groups(id) on delete set null
- weight integer not null default 1
- created_at timestamptz default now()
- updated_at timestamptz default now()
- check (user_a <> user_b)

source permitido:
- same_place
- same_group
- same_event
- shared_topic
- manual

Agregar índices:
- user_places(user_id)
- user_places(place_id)
- topic_tags(slug)
- message_topic_tags(message_id)
- message_topic_tags(topic_tag_id)
- place_topics(place_id, weight desc)
- user_topic_interests(user_id)
- user_connections(user_a)
- user_connections(user_b)
- user_connections(place_id)
- user_connections(group_id)
- user_connections(event_id)

Activar RLS en todas las tablas nuevas.

No hacer DROP.
No borrar datos.
No modificar tablas Stage 1 salvo que sea estrictamente necesario.

Tarea 4 — Policies graph-ready

Crear:

supabase/graph-ready-policies.sql

Policies mínimas:

topic_tags:
- authenticated puede leer.
- authenticated puede insertar topic_tags.

message_topic_tags:
- authenticated puede leer si puede leer el mensaje asociado.
- authenticated puede insertar si el mensaje pertenece al usuario o si acaba de crearlo.

place_topics:
- authenticated puede leer.
- authenticated puede insertar/update mediante usuarios autenticados.
- mantener restricciones razonables; no permitir delete abierto.

user_places:
- usuario puede leer sus propias relaciones.
- usuario puede insertar/update sus propias relaciones.
- usuario no puede escribir relaciones de otro usuario.

user_topic_interests:
- usuario puede leer sus propios intereses.
- usuario puede insertar/update/delete sus propios intereses.
- usuario no puede manipular intereses de otro usuario.

user_connections:
- usuario puede leer conexiones donde participa.
- inserts controlados:
  - usuario puede crear conexión donde user_a = auth.uid() o user_b = auth.uid()
  - no puede crear conexión entre dos terceros.

No abrir todo públicamente.
No usar service_role en app cliente.

Tarea 8 — Integrar hashtags/topics en mensajes

En el flujo de envío de mensaje:

1. Enviar place_message como ya funciona.
2. Extraer hashtags del body.
3. Si hay hashtags:
   - crear/obtener topic_tags.
   - crear message_topic_tags.
   - actualizar place_topics.
   - opcionalmente actualizar user_topic_interests con source = hashtag.
4. Si falla tagging:
   - no revertir el mensaje.
   - documentar/loggear de forma segura.

Hashtags válidos:
- #tennis
- #japonés
- #skate
- #lectura
- #cafe

Soportar Unicode simple si es posible.
Evitar duplicados.
