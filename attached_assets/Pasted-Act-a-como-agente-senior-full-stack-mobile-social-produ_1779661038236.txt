Tarea 3 — Diseñar tabla de notificaciones internas

Crear:

supabase/notifications.sql

Debe ser idempotente y no destructivo.

Crear tabla:

in_app_notifications

Campos:
- id uuid primary key default gen_random_uuid()
- user_id uuid not null references profiles(id) on delete cascade
- actor_id uuid references profiles(id) on delete set null
- place_id uuid references places(id) on delete set null
- group_id uuid references groups(id) on delete set null
- event_id uuid references events(id) on delete set null
- report_id uuid references reports(id) on delete set null
- type text not null
- title text not null
- body text
- read_at timestamptz
- created_at timestamptz default now()

Tipos sugeridos:
- group_join_request
- group_member_approved
- group_member_rejected
- event_rsvp_changed
- report_created
- report_status_changed
- geofence_blocked_post
- topic_trending

Agregar índices:
- in_app_notifications(user_id, created_at desc)
- in_app_notifications(user_id, read_at)
- in_app_notifications(type)
- in_app_notifications(group_id)
- in_app_notifications(event_id)
- in_app_notifications(place_id)

Activar RLS.

supabase/notifications-policies.sql

Tarea 6 — Integrar notificaciones en flujos existentes

Integrar notificaciones internas en:

1. Solicitud de ingreso a grupo:
- cuando usuario B solicita ingreso a grupo approval_required
- crear notificación para owner del grupo:
  “Nueva solicitud para unirse a tu grupo”

2. Aprobación/rechazo de miembro:
- cuando owner aprueba/rechaza
- crear notificación para solicitante:
  “Tu solicitud fue aprobada/rechazada”

3. RSVP:
- cuando usuario cambia RSVP en evento
- crear notificación para creador del evento:
  “Alguien cambió su asistencia”

4. Reportes:
- cuando se crea report
- crear notificación para moderadores si se puede resolver lista de moderators
- si no, documentar que moderation inbox sigue siendo fuente primaria

No romper si falla notificación.
La acción principal debe completarse aunque la notificación falle, pero debe loggear error seguro.
